# Requirements Document

## Introduction

This feature integrates the FAQ Accordion block (`wpbits/faq-accordion`) with WordPress's native block supports system (`theme.json`). The block currently uses hardcoded CSS values for colors, typography, spacing, and borders. By declaring support for these design categories in `block.json`, the block will inherit theme design tokens, expose standard WordPress editor panels (color, typography, spacing, border) in the sidebar, and allow themes to control the block's appearance through their `theme.json` configuration — all without custom CSS. This is the "free" tier implementation; a custom CSS editor will be a separate "pro" feature.

## Glossary

- **FAQ_Block**: The `wpbits/faq-accordion` block that displays FAQ items in an accordion format using native `<details>`/`<summary>` elements.
- **Block_Supports**: The `supports` property in `block.json` that declares which WordPress design features the block integrates with, enabling automatic UI panels and CSS output.
- **Theme_JSON**: The WordPress `theme.json` configuration file that defines design tokens (colors, typography, spacing) which blocks can consume via CSS custom properties.
- **Design_Tokens**: CSS custom properties (e.g., `--wp--preset--color--primary`) generated by WordPress from `theme.json` palette, typography, and spacing definitions.
- **Color_Support**: The block supports declaration that enables text color, background color, and link color panels in the editor sidebar.
- **Typography_Support**: The block supports declaration that enables font size, font family, font weight, line height, letter spacing, and text decoration panels in the editor sidebar.
- **Spacing_Support**: The block supports declaration that enables padding and margin controls in the editor sidebar.
- **Border_Support**: The block supports declaration that enables border color, style, width, and radius controls in the editor sidebar.
- **CSS_Custom_Properties**: CSS `var()` references used in the block's stylesheet to consume values set by block supports or theme.json, enabling theme-controlled styling.
- **Editor_Sidebar**: The WordPress block editor's settings panel where block-specific controls (including supports-generated panels) appear when a block is selected.

## Requirements

### Requirement 1: Color Support Declaration

**User Story:** As a site owner, I want the FAQ Accordion block to respect my theme's color palette, so that the block matches the site's design without manual CSS overrides.

#### Acceptance Criteria

1. THE FAQ_Block SHALL declare `color` support in `block.json` with `text`, `background`, and `link` properties enabled.
2. WHEN the FAQ_Block is selected in the editor, THE Editor_Sidebar SHALL display the WordPress color panel with text color, background color, and link color pickers populated from the active theme's color palette.
3. WHEN a user selects a text color, THE FAQ_Block SHALL apply the selected color as an inline style or preset class to the block wrapper element on both the editor preview and the frontend.
4. WHEN a user selects a background color, THE FAQ_Block SHALL apply the selected background color as an inline style or preset class to the block wrapper element on both the editor preview and the frontend.
5. WHEN no color is explicitly set by the user, THE FAQ_Block stylesheet SHALL use CSS_Custom_Properties that reference inherited theme values for border color, header background, and accent color instead of the current hardcoded values (`#ddd`, `#f9f9f9`, `#0073aa`).
6. IF a theme defines color presets in its theme.json, THEN THE FAQ_Block color pickers SHALL display those presets as selectable options.

### Requirement 2: Typography Support Declaration

**User Story:** As a site owner, I want to control the FAQ Accordion's font settings through the standard WordPress typography panel, so that headings and body text match the site's typographic hierarchy.

#### Acceptance Criteria

1. THE FAQ_Block SHALL declare `typography` support in `block.json` with `fontSize` and `lineHeight` properties enabled.
2. WHEN the FAQ_Block is selected in the editor, THE Editor_Sidebar SHALL display the WordPress typography panel with font size and line height controls.
3. WHEN a user selects a font size, THE FAQ_Block SHALL apply the selected font size as an inline style or preset class to the block wrapper element on both the editor preview and the frontend.
4. WHEN no font size is explicitly set by the user, THE FAQ_Block stylesheet SHALL use CSS_Custom_Properties for font sizing instead of the current hardcoded `font-size: 1em` on the summary element.
5. IF a theme defines font size presets in its theme.json, THEN THE FAQ_Block typography panel SHALL display those presets as selectable options.

### Requirement 3: Spacing Support Declaration

**User Story:** As a site owner, I want to adjust the FAQ Accordion's padding and margin through the standard WordPress spacing panel, so that I can control the block's spacing without writing CSS.

#### Acceptance Criteria

1. THE FAQ_Block SHALL declare `spacing` support in `block.json` with `padding` and `margin` properties enabled.
2. WHEN the FAQ_Block is selected in the editor, THE Editor_Sidebar SHALL display the WordPress spacing panel with padding and margin controls.
3. WHEN a user sets padding values, THE FAQ_Block SHALL apply the padding as inline styles to the block wrapper element on both the editor preview and the frontend.
4. WHEN a user sets margin values, THE FAQ_Block SHALL apply the margin as inline styles to the block wrapper element on both the editor preview and the frontend.
5. WHEN no spacing is explicitly set by the user, THE FAQ_Block stylesheet SHALL use CSS_Custom_Properties for internal padding values (replacing the hardcoded `1em 1.25em` padding on summary and content elements) that can be overridden by theme.json `spacing` definitions.

### Requirement 4: Border Support Declaration

**User Story:** As a site owner, I want to control the FAQ Accordion's border styling through the standard WordPress border panel, so that borders match the site's design language.

#### Acceptance Criteria

1. THE FAQ_Block SHALL declare `border` support in `block.json` with `color`, `style`, `width`, and `radius` properties enabled.
2. WHEN the FAQ_Block is selected in the editor, THE Editor_Sidebar SHALL display the WordPress border panel with color, style, width, and radius controls.
3. WHEN a user sets border properties, THE FAQ_Block SHALL apply the border values as inline styles to the block wrapper element on both the editor preview and the frontend.
4. WHEN no border properties are explicitly set by the user, THE FAQ_Block stylesheet SHALL use CSS_Custom_Properties for border color and radius (replacing the hardcoded `1px solid #ddd` border and `4px` border-radius) that can be overridden by theme.json `border` definitions.

### Requirement 5: CSS Custom Property Migration

**User Story:** As a theme developer, I want the FAQ Accordion block to use CSS custom properties for all its visual styling, so that I can control its appearance through theme.json without writing block-specific CSS.

#### Acceptance Criteria

1. THE FAQ_Block stylesheet SHALL replace the hardcoded border color `#ddd` with a CSS custom property that falls back to the current value (e.g., `var(--wp--custom--faq-accordion--border-color, currentColor)` or a suitable inherited value).
2. THE FAQ_Block stylesheet SHALL replace the hardcoded header background `#f9f9f9` with a CSS custom property that falls back to the current value (e.g., `var(--wp--custom--faq-accordion--header-background, #f9f9f9)`).
3. THE FAQ_Block stylesheet SHALL replace the hardcoded accent color `#0073aa` (used for open border and focus outline) with a CSS custom property that falls back to the current value (e.g., `var(--wp--custom--faq-accordion--accent-color, #0073aa)`).
4. THE FAQ_Block stylesheet SHALL replace the hardcoded hover background `#f0f0f0` with a CSS custom property that falls back to the current value (e.g., `var(--wp--custom--faq-accordion--header-hover-background, #f0f0f0)`).
5. THE FAQ_Block stylesheet SHALL replace the hardcoded separator color `#eee` (content panel border-top) with a CSS custom property that falls back to the current value (e.g., `var(--wp--custom--faq-accordion--separator-color, #eee)`).
6. THE FAQ_Block stylesheet SHALL replace the hardcoded padding values `1em 1.25em` with CSS custom properties that fall back to the current values for header and content padding.
7. WHEN a theme defines custom values under a `custom.faq-accordion` key in theme.json, THE FAQ_Block SHALL use those values as the effective styling through the generated CSS custom properties.
8. WHEN no custom theme values or user overrides are set, THE FAQ_Block SHALL render identically to its current appearance using the CSS custom property fallback values.

### Requirement 6: Theme.json Block-Level Styling

**User Story:** As a theme developer, I want to style the FAQ Accordion block through my theme.json file, so that the block integrates with the rest of my theme without plugin-specific CSS.

#### Acceptance Criteria

1. THE FAQ_Block SHALL be targetable in theme.json under the `styles.blocks["wpbits/faq-accordion"]` key for color, typography, spacing, and border overrides.
2. WHEN a theme sets `styles.blocks["wpbits/faq-accordion"].color.text` in theme.json, THE FAQ_Block SHALL render with the specified text color on the frontend and in the editor preview.
3. WHEN a theme sets `styles.blocks["wpbits/faq-accordion"].color.background` in theme.json, THE FAQ_Block SHALL render with the specified background color on the frontend and in the editor preview.
4. WHEN a theme sets `styles.blocks["wpbits/faq-accordion"].typography.fontSize` in theme.json, THE FAQ_Block SHALL render with the specified font size on the frontend and in the editor preview.
5. WHEN a theme sets `styles.blocks["wpbits/faq-accordion"].spacing.padding` in theme.json, THE FAQ_Block SHALL render with the specified padding on the frontend and in the editor preview.
6. WHEN a theme sets `styles.blocks["wpbits/faq-accordion"].border` properties in theme.json, THE FAQ_Block SHALL render with the specified border styling on the frontend and in the editor preview.
7. WHEN a user explicitly sets a value through the Editor_Sidebar controls, THE user-set value SHALL take precedence over the theme.json block-level value.

### Requirement 7: Backward Compatibility

**User Story:** As an existing user, I want the FAQ Accordion block to look the same after the update if my theme does not use theme.json, so that the update does not break my site's appearance.

#### Acceptance Criteria

1. WHEN no theme.json is active and no user overrides are set, THE FAQ_Block SHALL render with visual styling identical to the current hardcoded appearance (borders: `1px solid #ddd`, header background: `#f9f9f9`, accent: `#0073aa`, padding: `1em 1.25em`, border-radius: `4px`).
2. THE FAQ_Block CSS custom properties SHALL define fallback values that match the current hardcoded values exactly.
3. WHEN the block supports are declared, THE FAQ_Block SHALL continue to support the existing `html: false`, `align: ["wide", "full"]`, and `multiple: false` settings without modification.
4. WHEN an existing block instance (saved before this update) is loaded in the editor, THE FAQ_Block SHALL render without block validation errors and without requiring manual re-saving.
5. IF a classic theme without theme.json support is active, THEN THE FAQ_Block SHALL render using the CSS custom property fallback values, producing the same visual output as the pre-update version.
