# Requirements Document

## Introduction

The FAQ Generator Service is the main orchestration layer for the AI FAQ Generator plugin. It coordinates the full FAQ generation workflow: fetching WordPress post data by ID, building a prompt via the Prompt_Builder, calling the AI provider through the AIProviderInterface, and returning the parsed FAQ array. The service lives at `includes/services/class-faq-generator.php` and provides a single public entry point (`generateFaqs(int $post_id): array`) that the REST API or AJAX handlers consume.

## Glossary

- **Faq_Generator**: The orchestration service class (`includes/services/class-faq-generator.php`) that coordinates FAQ generation from a WordPress post.
- **Post_ID**: A positive integer identifying a WordPress post or page whose content is used for FAQ generation.
- **Prompt_Builder**: The existing service (`includes/services/class-prompt-builder.php`) that constructs prompt strings from post data and settings.
- **AIProviderInterface**: The contract (`includes/interfaces/class-ai-provider-interface.php`) implemented by AI clients such as OpenAIClient.
- **FAQ_Array**: The return value of the generation process — an indexed array of associative arrays, each containing a "question" string key and an "answer" string key.
- **WP_Post**: A WordPress post object retrieved via `get_post()`, containing title and content fields.
- **FAQ_Count**: An optional integer setting (1–20) specifying how many FAQ items to generate, read from `afg_settings` option.

## Requirements

### Requirement 1: Accept Post ID and Fetch Post Data

**User Story:** As a plugin developer, I want the Faq_Generator to accept a post ID and retrieve the corresponding post data, so that FAQ generation is driven by actual WordPress content.

#### Acceptance Criteria

1. WHEN a Post_ID greater than zero is provided and corresponds to a published WordPress post or page, THE Faq_Generator SHALL retrieve the WP_Post object using the WordPress `get_post()` function.
2. WHEN the Post_ID corresponds to a published WordPress post or page, THE Faq_Generator SHALL extract the post title and post content from the WP_Post object for use in prompt building.
3. IF the Post_ID does not correspond to an existing WordPress post, THEN THE Faq_Generator SHALL throw a RuntimeException with an error message indicating the post was not found.
4. IF the Post_ID is zero or negative, THEN THE Faq_Generator SHALL throw an InvalidArgumentException with an error message indicating the post ID is invalid.
5. IF the Post_ID corresponds to an existing WordPress post that does not have a post status of "publish", THEN THE Faq_Generator SHALL throw a RuntimeException with an error message indicating the post is not published.

### Requirement 2: Build Prompt via Prompt_Builder

**User Story:** As a plugin developer, I want the Faq_Generator to delegate prompt construction to the Prompt_Builder, so that prompt logic remains encapsulated and reusable.

#### Acceptance Criteria

1. WHEN post data has been successfully retrieved, THE Faq_Generator SHALL call the Prompt_Builder `build()` method with the post title as the first argument and the post content as the second argument, and SHALL use the returned prompt string for the subsequent AI provider call.
2. IF a `faq_count` key exists in the `afg_settings` WordPress option and its value is non-null, THEN THE Faq_Generator SHALL cast that value to an integer and pass it to the Prompt_Builder `build()` method as the third argument.
3. IF the `afg_settings` WordPress option does not exist, or the option exists but does not contain a `faq_count` key, or the `faq_count` value is null, THEN THE Faq_Generator SHALL pass null as the FAQ_Count argument to the Prompt_Builder, allowing the Prompt_Builder to apply its default value of 5.
4. THE Faq_Generator SHALL read the `afg_settings` WordPress option using the `get_option()` function with an empty array as the default value.

### Requirement 3: Call AI Provider

**User Story:** As a plugin developer, I want the Faq_Generator to send the built prompt to the AI provider, so that FAQ content is generated by the configured AI service.

#### Acceptance Criteria

1. WHEN the Prompt_Builder returns a prompt string, THE Faq_Generator SHALL pass that prompt string to the AIProviderInterface `generateFaqs()` method and return the resulting `array<int, array{question: string, answer: string}>` to the caller.
2. THE Faq_Generator SHALL accept the AIProviderInterface as a constructor dependency, so that the AI provider implementation is interchangeable.
3. THE Faq_Generator SHALL accept the Prompt_Builder as a constructor dependency, so that prompt construction logic is interchangeable.
4. IF the AIProviderInterface `generateFaqs()` method throws a RuntimeException, THEN THE Faq_Generator SHALL propagate the exception to the caller without suppressing it.

### Requirement 4: Return FAQ Array

**User Story:** As a plugin developer, I want the Faq_Generator to return a structured array of FAQ pairs, so that consumers receive a consistent data format.

#### Acceptance Criteria

1. WHEN the AI provider returns a successful response, THE Faq_Generator SHALL return the FAQ_Array directly as the return value of the AIProviderInterface `generateFaqs()` method without modification.
2. THE Faq_Generator SHALL return the FAQ_Array as a zero-indexed array where each element is an associative array containing exactly two keys: "question" (non-empty string) and "answer" (non-empty string), with no additional keys present in any element.
3. WHEN the AI provider returns an empty array, THE Faq_Generator SHALL return an empty array without throwing an exception.
4. IF any element in the FAQ_Array contains a "question" or "answer" value that is empty or consists only of whitespace characters, THEN THE Faq_Generator SHALL exclude that element from the returned array.

### Requirement 5: Handle Errors Gracefully

**User Story:** As a plugin developer, I want the Faq_Generator to handle errors from any step in the pipeline, so that callers receive clear error information without unhandled exceptions.

#### Acceptance Criteria

1. IF the AIProviderInterface `generateFaqs()` method throws a RuntimeException, THEN THE Faq_Generator SHALL re-throw the exception to the caller with the original exception message string unchanged.
2. IF the `get_post()` call returns null for the given Post_ID, THEN THE Faq_Generator SHALL throw a RuntimeException with a message that contains the numeric Post_ID value that was requested.
3. IF the WP_Post object has an empty string title and empty string content, THEN THE Faq_Generator SHALL still invoke the Prompt_Builder and AIProviderInterface without throwing an exception, delegating empty-input handling to the Prompt_Builder.
4. IF the WP_Post object has a non-empty title but an empty string content, or a non-empty content but an empty string title, THEN THE Faq_Generator SHALL proceed with FAQ generation using the available field without throwing an exception.
5. IF the AIProviderInterface `generateFaqs()` method returns an empty array, THEN THE Faq_Generator SHALL return the empty array to the caller without throwing an exception.

### Requirement 6: Dependency Injection

**User Story:** As a plugin developer, I want the Faq_Generator to receive its dependencies through the constructor, so that the service is testable and follows the dependency inversion principle.

#### Acceptance Criteria

1. THE Faq_Generator SHALL accept an AIProviderInterface instance as the first constructor parameter.
2. THE Faq_Generator SHALL accept a Prompt_Builder instance as the second constructor parameter.
3. THE Faq_Generator SHALL NOT instantiate the AIProviderInterface or Prompt_Builder internally.
4. THE Faq_Generator SHALL store the injected dependencies as private properties for use during FAQ generation.
