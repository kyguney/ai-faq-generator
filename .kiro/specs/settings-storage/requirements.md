# Requirements Document

## Introduction

This feature implements the settings storage system for the AI FAQ Generator WordPress plugin. It provides a React-based settings page using WordPress block editor components (TextControl, SelectControl, RangeControl) that persists configuration to the WordPress Options API. The settings include API provider selection, API key, model name, temperature, and FAQ count. The implementation ensures input sanitization, CSRF protection via nonces, and prevents API key exposure in page source.

## Glossary

- **Settings_Page**: The React-rendered admin page where users configure the AI FAQ Generator plugin options
- **Options_API**: The WordPress `get_option()` / `update_option()` system for persisting plugin settings
- **REST_Endpoint**: A custom WordPress REST API route used to read and write settings from the React frontend
- **Nonce**: A WordPress security token generated by `wp_create_nonce()` and verified by `wp_verify_nonce()` or `check_ajax_referer()` to prevent CSRF attacks
- **Sanitizer**: A server-side function that validates and cleans user input before persisting to the database
- **Settings_Object**: The structured data object containing all plugin settings fields (provider, api_key, model, temperature, faq_count)
- **API_Provider**: One of the supported AI service providers: OpenAI, OpenRouter, Ollama, DeepSeek, LocalAI, or LM Studio

## Requirements

### Requirement 1: Settings Persistence

**User Story:** As a WordPress administrator, I want plugin settings to be saved to the database, so that my configuration persists across page loads.

#### Acceptance Criteria

1. WHEN an administrator submits the settings form, THE REST_Endpoint SHALL persist the Settings_Object to the Options_API using `update_option()`
2. WHEN the Settings_Page loads, THE REST_Endpoint SHALL retrieve the Settings_Object from the Options_API using `get_option()` and return it to the frontend
3. THE Options_API SHALL store all settings under a single option key `afg_settings`
4. WHEN no settings have been saved previously, THE REST_Endpoint SHALL return default values: provider "openai", model "gpt-4o", temperature 0.7, faq_count 5, and an empty api_key

### Requirement 2: Settings Form UI

**User Story:** As a WordPress administrator, I want a settings form with appropriate input controls, so that I can configure the AI provider and generation parameters.

#### Acceptance Criteria

1. THE Settings_Page SHALL render an API_Provider field as a SelectControl with options: OpenAI, OpenRouter, Ollama, DeepSeek, LocalAI, LM Studio
2. THE Settings_Page SHALL render an API Key field as a TextControl with type "password" so the value is masked during input
3. THE Settings_Page SHALL render a Model field as a TextControl accepting free-text input (e.g., "gpt-4o", "gpt-3.5-turbo")
4. THE Settings_Page SHALL render a Temperature field as a RangeControl with minimum 0.0, maximum 2.0, and step 0.1
5. THE Settings_Page SHALL render a FAQ Count field as a RangeControl with minimum 1, maximum 20, and step 1
6. THE Settings_Page SHALL use only WordPress core block editor components from `@wordpress/components`

### Requirement 3: Input Validation and Sanitization

**User Story:** As a WordPress administrator, I want the system to validate my inputs, so that only valid configuration values are stored.

#### Acceptance Criteria

1. WHEN the provider value is not one of the allowed API_Provider values, THEN THE Sanitizer SHALL reject the input and retain the previous stored value
2. WHEN the temperature value is outside the range 0.0 to 2.0, THEN THE Sanitizer SHALL clamp it to the nearest boundary
3. WHEN the faq_count value is outside the range 1 to 20, THEN THE Sanitizer SHALL clamp it to the nearest boundary
4. WHEN the model field is empty or contains only whitespace, THEN THE Sanitizer SHALL reject the input and retain the previous stored value
5. THE Sanitizer SHALL apply `sanitize_text_field()` to the model and api_key values before storage

### Requirement 4: Security

**User Story:** As a WordPress administrator, I want the settings page to be secure, so that unauthorized users cannot modify settings or steal my API key.

#### Acceptance Criteria

1. WHEN a REST request is received without a valid Nonce, THEN THE REST_Endpoint SHALL return a 403 Forbidden response
2. WHEN a REST request is received from a user without the `manage_options` capability, THEN THE REST_Endpoint SHALL return a 403 Forbidden response
3. THE Settings_Page SHALL NOT render the stored API key value in the HTML page source; the frontend SHALL display a placeholder when a key exists
4. WHEN the API key is retrieved via the REST_Endpoint, THE REST_Endpoint SHALL return a masked representation (e.g., "sk-****...****") instead of the full key
5. THE REST_Endpoint SHALL use the WordPress REST API nonce mechanism (`wp_rest` nonce passed via `X-WP-Nonce` header) for CSRF protection

### Requirement 5: Frontend-Backend Communication

**User Story:** As a WordPress administrator, I want the settings page to load and save without full page reloads, so that the experience is smooth and responsive.

#### Acceptance Criteria

1. THE Settings_Page SHALL use the WordPress REST API (`wp.apiFetch`) to read settings on page load
2. THE Settings_Page SHALL use the WordPress REST API (`wp.apiFetch`) to write settings on form submission
3. WHEN settings are saved successfully, THE Settings_Page SHALL display a success notice using the WordPress `@wordpress/components` Notice component
4. IF a save request fails, THEN THE Settings_Page SHALL display an error notice with the failure reason
5. WHILE a save request is in progress, THE Settings_Page SHALL disable the submit button and show a loading indicator

### Requirement 6: Script and Style Enqueuing

**User Story:** As a developer, I want the settings page assets to load only on the settings page, so that the plugin does not affect other admin pages.

#### Acceptance Criteria

1. WHEN the current admin page is the AI FAQ Generator settings page, THE Admin class SHALL enqueue the compiled React bundle and its stylesheet
2. WHEN the current admin page is not the AI FAQ Generator settings page, THE Admin class SHALL NOT enqueue the settings assets
3. THE Admin class SHALL pass the REST API URL, nonce, and current settings to the frontend via `wp_localize_script()`
